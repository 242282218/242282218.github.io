## 2. 阶段一：可用性（黑窗 + 卡顿）

目标：打开软件不再出现任何 cmd 窗口；写字过程不再卡顿；保存路径不联网。
顺序很重要：**A1 先在隔离的测试数据目录复现并记录基线**，再逐项修复与回归；不得污染真实工作区或真实远端。

### A1. 复现与基线（不改功能代码）

1. 构建 release 产物，在 `GUANLANZHI_WRITER_DATA_DIR` 指向的**独立测试目录**复现未连接与已连接启动；后者只连接本机测试仓库，记录子窗口数量、时长与进程来源。
2. 在测试工作区准备小/大两组文章（例如 10 与 50 篇；仅复制测试夹具，不动真实文章），记录启动可输入时间、输入期间本软件派生的子进程数、保存耗时和空闲 CPU。观察进程以**父子关系与调用点**为准，不把系统里其他应用的 `git.exe` 算进来。正常退出并核对软件创建的进程是否清理；不得对未知 PID 批量 `taskkill`。
3. 以真实窗口操作及调用耗时/调用次数定位停顿；Tauri 2.11.6 的同步命令有直接执行的机制依据，但**不能仅凭签名推断每条命令都造成可感知卡顿**。需要探针时只用测试夹具，测试后移除；记录实际等待发生在 UI、IPC 还是后台工作线程。

### A2. 按热点迁移阻塞命令

1. 锁定版本 Tauri 2 的同步 `#[tauri::command]` 包装层直接执行命令；异步包装层将任务交给运行时（`Cargo.lock` 的 Tauri 2.11.6、tauri-macros 2.6.3；参见 [官方命令文档](https://v2.tauri.app/develop/calling-rust/)）。**同步签名有阻塞机制依据，但实际卡顿程度仍以 A1 实测为准。**优先完成 A5 的去联网和去重复扫描，再将仍执行阻塞 Git/磁盘/进程操作的热点命令按需迁移，不能只因数量是 38 就全量改写；纯内存/短命令保留原状。
2. 对需要等待长任务的 IPC 命令，用 `async fn` 接收请求，将原有同步业务函数放入 `tauri::async_runtime::spawn_blocking` 并 `await` 结果；**只写 `async fn` 却在其中直接运行阻塞工作不算完成**。`spawn_blocking` 要求闭包 `Send + 'static`，不能把借用的 `State<'_, AppState>` 直接移入闭包；可移入拥有型 `AppHandle`，在闭包内通过 `Manager::state::<AppState>()` 取得状态，或移动所需的拥有型数据。先以一个命令编译和测试验证模式，再推广到经测量的热点。
3. 不跨 `await` 持有 Mutex 锁；保留现有按篇远端写操作互斥。`TaskQueue` 当前按 `remote:<article_id>` 分键，**不是**全局远端队列，忙时返回错误且 `pending` 只是记录，不会自动执行。异步打开文章的只读 fetch 应去重/限制并发，避免频繁切换文章积压；只有实测需要时再加独立的全局读取限流，不改同步/发布既有互斥语义。
4. 为同篇文章并发保存/刷新/同步添加针对性的回归测试：较旧请求晚返回时不得覆盖较新的文章内容或把旧远端结论当成当前状态。

### A3. 子进程全部静默（黑窗修复）

1. 在 `util.rs` 建立统一的子进程创建/标志设置入口；`program_command()` 与直接 `Command::new` 的调用者都要检查：

   ```rust
   #[cfg(windows)]
   pub fn hide_console(cmd: &mut std::process::Command) -> &mut std::process::Command {
       use std::os::windows::process::CommandExt;
       const CREATE_NO_WINDOW: u32 = 0x0800_0000;
       cmd.creation_flags(CREATE_NO_WINDOW)
   }
   #[cfg(not(windows))]
   pub fn hide_console(cmd: &mut std::process::Command) -> &mut std::process::Command { cmd }
   ```
   如需代码注释只写英文且只解释无法从实现直接读出的约束；实装时确认其他 `creation_flags` 调用没有覆盖该位。

2. 改造点（逐一，不得遗漏）：
   - `util.rs:251 program_command()` —— 让返回值默认带上标志（最省事的收口方式）；
   - `git.rs:59`、`git.rs:223`、`publish.rs:679`、`testkit.rs:187/203`、`trash.rs:1135` 等直接 `Command::new` 的位置；
   - `app_commands.rs:883`（curl）、`preview.rs:175`（taskkill）、`preview.rs:385`（cmd /c mklink）；
   - `preview.rs:541`（`pnpm exec astro dev`，长期进程）——同样静默，输出已重定向到日志文件。
3. **逐调用点核对 stdin 与凭据交互**：非交互探测可用 `Stdio::null()` 并设置合理超时；有意通过 stdin 传内容的调用必须保留管道（如 `publish.rs` 中的 `Stdio::piped()`），不能给所有 Git 一律设 null。无控制台不等于认证成功；认证受阻要返回明确错误，不隐藏或丢弃原有凭据助手行为。
4. release GUI 子系统的 CLI 输出需在 cmd/PowerShell 实测；按 D14 在 `lib.rs` 的 CLI 分支尝试 `AttachConsole(ATTACH_PARENT_PROCESS)`（Windows）并在需要时重新绑定 stdout/stderr，确保 `--self-test` 有可见输出和正确退出码。失败时提供可检查的诊断方式，不因无父终端影响双击 GUI 启动；具体标准流实现须以 Windows 实测确认。

### A4. 启动路径不再跑外部命令

1. 启动路径上的 `connection_status` 当前调用 `check_toolchain()` 依次执行 `git`、`node`、`pnpm --version`。将连接状态读取与环境检查分开：启动先显示配置与**环境尚未检查/上次检查时间**，后台或用户显式触发真实版本检查；避免在首帧前同步等待探测结果。
2. 查 PATH/已知路径只能说明**找到候选文件**，不能证明程序可执行或 Node 版本满足要求；连接、预览或发布需要工具链时须基于实际检查结果判断，缓存有时间戳与失效语义，不显示虚假的「已通过」。未连接启动时的零子进程目标以进程跟踪验证。
3. `deployment_status`（curl）的前端调用时机以现有调用点核实后再调整；保持已有超时，状态失败时明确显示「待确认」，不要将网络失败解释为部署成功。

### A5. 先补状态正确性，再使保存路径离线（D13）

1. **先扩展状态协议并补测试**：当前 Rust `RemoteSync`/`SiteState` 和前端对应类型没有「未核对」态，`workspace.scan/read` 对缺失快照使用默认值；`remote_snapshots` 的 `.ok().flatten()` 会把 fetch 失败、分支确实不存在、单篇读取失败混成 `None`。为 writing/main **分别**表示「未核对/失败」「已核对且分支或文章不存在」「已核对并有内容」，保留核对时间及所依据的远端头；映射到列表、文章状态、筛选与操作提示。未核实时不显示「已同步」「已上线」等肯定结论，历史结论只能带时间作为历史信息展示；只核对成功一支不能推定另一支。不得改变同步/发布前实际冲突核对的安全语义。
2. `useArticle.ts` 的 `flush()` 移除保存成功后的 `await refreshList()`。用保存返回值更新当前文章的**本地字段**和列表对应项；`workspace.save` 返回的默认快照不是远端事实，不能照搬它的远端状态。本地原文哈希变化后，将旧远端结论标为待核对，不能继续沿用旧「已同步」徽标。若切换文章前 `flush()` 失败或仍有未落盘内容，保持原文章与草稿，不得直接替换。
3. `list_articles` / `read_article` 只取本地数据和**仍可证明有效的**缓存，不隐式 fetch；`openArticle` 在本地读完并展示后，单独发起该篇的异步远端核对（打开一次），手动刷新可显式重查；同步/发布继续在自己的预检流程核对。后台结果回写时核对文章 ID、本地内容版本及请求序号，丢弃切篇后返回的旧请求；连续打开要去重/限流，避免任务积压。
4. 远端核对设置超时并提供成功/失败反馈；**超时或断网不能复用旧结果冒充当前核对**。先按实际耗时决定是否需要持久缓存；若有缓存，以仓库标识＋分支＋头提交＋文章路径为键，连同「该头下确认不存在」一并缓存，且必须成功取得当前头后才可复用。缓存不能替代网络可达性/远端新头验证。
5. 先通过移除保存后全量列表刷新取得收益；如仍有可复现的扫描热点，再按单篇保存增量更新、缓存解析结果/图片哈希。`(mtime, size)` 只能作为快路径：外部同尺寸改写或时间戳不变时须有重验/失效策略，关键状态以**磁盘原文字节哈希**为准，不能用 `render()` 规范化结果替代。保持受管路径的链接逃逸守卫。
6. 恢复快照与版本索引的 `sync_all()` 先保留；测量 400ms 快照写入及保存路径的实际瓶颈，优先去掉重复写/扫描。**不得仅因强杀测试通过就移除 fsync**：它不能证明断电耐久性。若测量显示非改不可，单列断电数据损失窗口及回归方案，经需求方确认后实施；正文写入耐久性不得降低。
7. 保持 `autoSaveDebounceMs` 可配置（默认 800ms），不擅自改变保存时机；新增失败、离线、快速切篇与迟到核对结果的回归测试。

### A6. 预览与 Vditor（阶段一内的止血）

1. `start_site_preview` 当前可能在命令内执行 `pnpm install`。把依赖准备与启动分开：缺依赖时先返回明确、可操作的「需准备依赖」状态；用户触发的独立准备任务报告进行中/成功/失败并去重，完成后重试启动。若设计为自动准备，须提供真实任务 ID、可查询状态及失败/超时处理，不能一边返回错误一边声称后台安装却没有任务。现有 Astro 真服务入口须保留。
2. 阶段一先测 Vditor 的实际输入开销；若是热点，只调整渲染防抖/高亮策略，并确保 `sanitize.ts` 每次**新内容**仍生效，不为了阶段二即将退役的代码引入复杂缓存。关闭 Vditor 的高亮不会使其即时预览自动等于 Astro 页面。
3. `public/vditor` 阶段一不清理（阶段二替换后再处理）。

### A7. 构建档位（有测量依据再改）

1. 在同一测试工作区、同一机器分别测量修改前后的 release 产物；仅在 Rust 侧仍有可复现的 CPU 热点时，试验 `opt-level = 3` 与现有 `"s"` 的速度、体积与构建成本，择优保留。不要把 release 优化参数当作卡顿根因。
2. 开发构建的体验与用户安装的 release 包分开评估；不因 release 卡顿预设新增 `[profile.dev]`。
3. `tauri build` 用正常增量构建并实测 release；只有发生**缓存迁移引发的绝对路径残留**等可复现错误时，才针对性清理 release 缓存。`memory.md` 中的 `cargo clean --release` 案例针对移动 target 目录，不能推广为改 profile 的前置步骤。

### 3.3 即时预览对齐站点排版（D6）

**这是本阶段最容易做成假象的一环，按下面的分层实现。**

```
Markdown 原文
  → 前端解析器（先以 marked + GFM 作最小实现，与 Astro 产物对照）
  → 净化（复核现有 sanitize 白名单、URL 与图片策略后作用于结果）
  → 隔离容器中的站点正文样式受控快照
  → 即时预览（近似）／现有 Astro 真服务（最终判据）
```

1. **来源与隔离**：仅从仓库内已审阅的 `src/styles/global.css` 生成、随软件打包一份正文样式快照；先覆盖文章页 `.shell/.article/.prose` 的尺寸、配色与正文规则，预览独立隔离外壳的全局 CSS/暗色变量。不要运行时把 clone 的 CSS 直接塞进具备 Tauri IPC 权限的 WebView：工作区可变，`@import`、`url()` 和逃逸选择器会引入资源加载与样式注入风险。若将来确需运行时取工作区 CSS，应单独设计固定路径、链接/目录联接检查、大小上限、CSS 解析白名单及 URL/导入拒绝规则，并单独验证安全边界；当前阶段**不增加该 IPC 能力**。
2. **防漂移**：为快照新增测试，对固定源 `src/styles/global.css` 及实际用于预览的关键规则、变量与排版参数做可重复的生成/比对；差异使 `pnpm --dir apps/writer test` 失败。样式相等只证明快照未漂移，仍须在隔离预览中检查**计算样式**、媒体查询与元素结构。若抽取 CSS，需用可验证的选择器处理，不做简单字符串替换，尤其要确认 `:root` 变量真正落到预览根元素。
3. **语法与安全**：对照 Astro 7.3.5 的 Sätteri/GFM/智能标点与 Shiki 输出测试标题锚点、表格、任务列表、代码围栏、原生 HTML、链接及图片路径。`sanitizeHtml` 已用于 Vditor 输出，但迁移到 `marked` 之前须测试 `srcset` 多候选 URL、`data:` MIME、相对 URL 基址与链接协议；净化失败不得降级为直接注入原始 HTML。所有预览资源保持离线与既有 CSP/路径边界。
4. **字体与代码**：不打包 webfont；离线时系统字体回退导致的换行差异须在验收记录。站点 `.prose pre` 覆盖背景，但 Shiki 的子节点语法色仍存在；可先做安全的基础代码呈现，再按真实站点截图对比前景/背景/语法色，不得声称无高亮即等同站点。
5. **宽度与移动端**：桌面默认最大阅读列约 760px；375px 模式应模拟**375px 视口**及 `.shell` 内边距（站点在 `max-width:420px` 下改为 `width:calc(100% - 32px)`，此时正文可用宽约 343px），而非仅把 `.prose` 固定成 375px。媒体查询以视口而非容器判断，若采用容器模拟，需逐项验证规则与真实页面等价，否则标为布局近似。
6. **滚动同步**：先实现稳定的单向定位与关闭开关；只有双向按块同步被实际验证确有需求且不造成滚动反馈循环时再补，避免引入参考项目的整套依赖。
7. 用真实文章和小型语法样本对照软件预览与 `pnpm dev` 的文章页：逐项记录 HTML 结构、链接/图片行为、桌面与移动宽度的计算样式和截图差异。当前构建目录可能含陈旧产物，**必须重新构建或使用当前 dev 页面**，不得以旧 `dist/` 当验收基准。现有 Astro 真服务仍是最终网页效果判据。

### 3.4 样式抽屉（做什么 / 不做什么）

**做**：默认显示**站点原貌**，可选的本机阅读偏好必须明示「仅影响软件预览，不改变网站文章」。站点当前 `.prose` 基准是 16px 字号、2.05 行高、段落下边距 21px；软件原有 `lineHeight=175` 是旧编辑偏好，**不是**站点默认。

| 控件 | 取值与默认 | 作用范围 |
|---|---|---|
| 字号 | 站点 16px；可选 14/15/17/18px | 预览 `.prose` 的显式覆盖，非只改外层继承值 |
| 行距 | 站点 2.05；可选 1.5/1.65/1.75/1.9 | 预览 `.prose` 的显式覆盖 |
| 段间距 | 站点 21px；可选缩放系数 | 预览 `.prose p`，调节后不再是网站原貌 |
| 预览列宽 | 站点桌面列 / 375px 模拟视口 | §3.3-5；手机列需计入页面内边距 |
| 还原站点 | 恢复当前站点快照的基准值 | 清除本机预览覆盖 |

**不做**：网站没有的可发布主题色、链接色、引用背景、标题样式、图注、Mac 代码块样式、自定义 CSS、社区主题、首行缩进、两端对齐、字体系列切换和代码主题切换；可选的本机字号/行距不是网站配置。

**与现有偏好的关系**：保留旧 `WritingPreferences` 字段以兼容已有本机设置，但区分**编辑器外观**与**站点预览**：`codeTheme` 仅在 CodeMirror 编辑区有实际消费者时继续使用，不控制站点预览；`fontSize`/`lineHeight` 的旧值不能静默覆盖「站点原貌」。新增预览设备/外壳深色偏好时沿用现有 Rust `serde` 与前端 `camelCase` 协议、提供默认值与迁移测试；若原有设置仍需入口，则保留偏好设置，样式抽屉仅放预览相关项。`autoSaveDebounceMs` 留在偏好设置。

### 3.5 技术栈落地（D8/D9）

1. 新增并锁定 `tailwindcss@4` + `@tailwindcss/vite` + `reka-ui` + `@lucide/vue` 的确定版本。

4. **深色模式**：仅作用于软件外壳，默认跟随系统；站点预览保持浅色，并在 `tokens.css` 的暗色变量与隔离容器并存时验证实际计算颜色。

## 4. 验收与回归总表

### 4.1 性能证据（D4：不设数字，但必须记录）

阶段一按 §A8 的记录表记录基线/修复后两列；阶段二结束再测一次，确认没有回退。
出现下列任一情况即视为**失败**（不是「体感」，是客观可见的）：

- 打开软件时出现意外的控制台黑窗（正常应用窗口不计）；
- 未主动刷新远端、未切换文章且未启动网站预览时，输入与自动保存派生 `git.exe` / `node.exe` / `cmd.exe`；打开文章触发的一次异步核对不算输入路径上的进程；
- 远端状态未知时显示为「已同步」；
- 保存失败却显示为已保存（`hasUnsavedChanges` 必须含 `failed`，见 `memory.md`）。

## 5. 风险与开放项

| 风险 | 影响 | 处理 |
|---|---|---|
| 同步命令可占用主线程，但全量 async 化无法自动消除阻塞 | 改动面扩大，保存后重复联网仍在 | 先去重复工作，再对经定位的重型命令用异步包装 + blocking 池，实测窗口流畅性 |
| 异步化引入并发与迟到结果 | 数据覆盖或旧状态覆盖新编辑 | 保留既有按篇写互斥，对只读核对加请求序号/版本校验，补竞态用例；不预设全局队列或新写锁 |
| 恢复快照写盘频率与耐久性 | 降低磁盘写入可能扩大异常断电的数据损失窗口 | 先测实际写入与卡顿，再决定是否改频率或 fsync；若必须降低耐久性，明确告知损失边界并单独取得确认 |
| 远端状态改为按需刷新 | 旧快照/默认值仍可能显示「已同步」「已上线」 | A5 先扩 Rust/TS 状态协议，区分两分支的未知、失败及确认不存在；同步调整筛选和徽标 |
| Tailwind v4 与 Vite 8 兼容性 | 界面构建可能受阻 | 先用确定版本验证并记录错误；优先试兼容的小版本组合，不静默降级或升级站点 |
| 前端解析器与 Astro/Shiki、预览 CSS 与文章页布局不一致 | 结构、代码着色、字体和手机列宽可能明显不同 | §3.3 用当前 Astro 页面逐项对照结构/计算样式/截图并记录差异；真服务为最终判据 |
| 换内核丢掉 IME/往返保护 | 中文输入体验回退 | §3.2-3/4 的专项手测 + 新回归测试 |
| 参考实现的身份信息（作者、邮箱、二维码）混入 | 事实性错误 | 只借结构与样式，不迁任何身份内容 |

**既有功能与待核实事实**

- 保留现有「启动真实站点服务并在浏览器查看」入口：它用于检查 Astro 最终渲染与站点交互，不由即时预览替代；启动过程仍须遵守阶段一的非阻塞与进程清理约束。
- 图片 `alt` 文本与站点 `figcaption` 的渲染规则应先查现有模板和产物，按实际行为实现与测试；没有需求时不新增图注字段或站点能力。

## 6. 给执行者的硬性约束

1. 保持 §0 已确认的产品目标；若文档的具体实现步骤与实际代码或测试结果冲突，先修正步骤并记录证据，不得为了遵循文字而破坏既有功能。
2. **不要改站点**（`src/`、`astro.config.mjs`、站点 `package.json`）；本软件对站点只读。
3. **不要动无关后端逻辑**：发布、撤下、删除、回收、同步、路径校验、哈希基准、单实例锁的既有语义；
   阶段一允许改的是「谁来调用、在哪个线程调用、调用的频率」，不是这些逻辑本身。
4. **安全边界不得放宽**：不新增任意 shell、任意文件系统读写、任意 Git 命令；新增子进程一律经 `util` 的统一入口。
5. **测试不得静默减少**：删除/改写测试必须在交付说明里列出原因与替代断言。
6. 每个阶段结束都要：更新 `docs/观澜志本地写作软件-交付说明.md`、更新根 `memory.md`（只写可复用经验）、
   报告「已验证 / 未验证」两栏，不编造结果。
7. 文档和界面文案用中文；**代码注释用英文**，且只说明代码无法表达的约束或原因，遵守项目优先约定。
8. 只在明确要求时提交；使用新分支，不直推 `main`。
